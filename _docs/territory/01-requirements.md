個人開発領を届け出る画像を作る前に、その画像が満たさなければならない条件を確かめる章です。画像の編集を始める前に一度読み、届け出る前に[6章「提出前のセルフチェック」](/docs/territory/checklist/)でもう一度確かめてください。

個人開発領は、参加者が届け出て設定する、旧ボーダー外における個人の開発の範囲です（旧ボーダー外の個人開発領に関するルール特例第1条第2号）。旧ボーダー外に個人開発領を設定しようとする参加者は、ディスコード鯖（Discordサーバー「3DS半分こするくらい仲良しクラフト中央委員会」）の専用チャンネルにその範囲を届け出なければなりません（旧ボーダー外の個人開発領に関するルール特例第2条第1項）。届出は、配布されている申請可能領域画像を編集した画像を、運営bot（OpsBot。Discord上の表示名は「DSクラフト運営bot」）の `/kaihatsu set` で送って行います（[5章「`/kaihatsu set` で提出する」](/docs/territory/submit/)）。

届け出る画像の条件は、**ルールの要件**と、**その他の要件**（運営botが届出を自動で処理するために必要な要件）の2つに分かれます。運営botは届いた画像をその場で確かめ、どちらか1つでも満たしていなければ届出を却下します。

## ルールの要件

届出は、次の3つの要件を満たすものでなければなりません（旧ボーダー外の個人開発領に関するルール特例第2条第2項）。

| 要件 | 内容 | 画像での確かめ方 |
|---|---|---|
| 広さ | 個人開発領は、25万平方ブロックを超えてはなりません（旧ボーダー外の個人開発領に関するルール特例第3条第1項） | 画像は1ピクセルが1ブロックです。透明でない（残した）ピクセルの数が、届け出る面積のブロック数になります。範囲がいくつかのタイルにまたがるときは、全部の画像の合計で250,000以下にします。数え方は[3章「GIMPで編集する」](/docs/territory/gimp/)・[4章「Photopeaで編集する」](/docs/territory/photopea/)の手順6にあります |
| 特定保護区域 | 個人開発領は、特定保護区域内の土地を含んではなりません（旧ボーダー外の個人開発領に関するルール特例第3条第2項） | 特定保護区域にかかる場所を残さない。特定保護区域かどうか分からない場所は、運営に確かめてください |
| 重なり | 個人開発領は、すでに設定されている他の個人開発領と重なってはなりません（旧ボーダー外の個人開発領に関するルール特例第3条第3項） | 配布画像のマゼンタ（明るい紫。他の人の個人開発領）を消す。マゼンタを残してよい場合は[2章「画像のダウンロード」](/docs/territory/download/)にあります |

- 面積は、範囲を囲む四角形の広さではなく、残したピクセルの数そのものです。離れた場所の消し忘れや、残したマゼンタも数に入ります。
- 要件を満たした届出のうち、どれが認められるか（同じ場所に何人かが届け出たときの順番など）は、[旧ボーダー外で開発したいときは（個人開発領）](/docs/life/personal-dev/)にあります。

## その他の要件

運営botが届出を自動で処理できるようにするために、画像には次の要件も必要です。運営botはこれらも確かめ、満たしていない画像の届出を却下します。

| 要件 | 内容 |
|---|---|
| 形式 | 中身が**PNG形式**の画像であること。編集ソフトからPNGで書き出します。JPEGなどで保存した画像の拡張子を `.png` に書き換えただけでは却下されます |
| 大きさ | 縦横が**5000×5000ピクセルちょうど**であること。ダウンロードした申請可能領域画像の大きさを変えない（切り抜き・拡大・縮小をしない）でください |
| 透明度 | どのピクセルも、**完全な不透明か完全な透明のどちらか**であること。境界にぼかし・グラデーション・アンチエイリアスを使わず、半透明のピクセルを作らないでください（下の「アンチエイリアスとは？」） |
| ファイル名 | `<地図番号2桁>_<Minecraftのユーザー名>.png` の形であること（下の「ファイル名の決まり」） |
| 紐づけ | ファイル名に書いたMinecraftのユーザー名が、`/authorise` でDiscordのアカウントと紐づけてある名前であること（[アカウントの紐づけ](/docs/opsbot/authorise/)） |

- 色は要件に入っていません。運営botは、ピクセルが透明かどうかだけで範囲を判定します。白に塗り替えるなど色を変える作業は、半透明のピクセルが混ざる原因になるので、ダウンロードしたままの色で書き出すのが安全です。
- 配布画像でもともと透明な場所は、旧ボーダー内など、届け出られない場所です。塗り足さないでください。塗り足した画像は運営botの判定を通ってしまうことがありますが、運営が承認を撤回する対象になります。

### ファイル名の決まり

運営botは、誰の届出か、どのタイルの画像かを、ファイル名だけで判断します。コマンドを実行した人ではありません。

- 先頭は、ダウンロードしたタイルの**地図番号**（01〜16）を2桁で書きます。地図番号が6なら `6_` ではなく `06_` です。
- 地図番号のあとに `_`（半角のアンダースコア）を1つ置き、続けて自分のMinecraftのユーザー名を書きます。最初の `_` より後ろは全部ユーザー名として読まれるので、ユーザー名に `_` が入っていてもそのまま書けます。
- ユーザー名は、`/whoami` で表示される、紐づけたときの名前と同じにします。
- 範囲がいくつかのタイルにまたがるときは、タイルごとに1枚ずつ画像を作り、それぞれの地図番号をファイル名に付けます。
- 自分の分を届け出るとき、ファイル名の形が合わない画像が1枚でも混じっていると、その届出は全体が却下されます。

範囲が旧ボーダー外にあるかどうかは、運営botが地図番号（01〜16のどれか）で確かめます。ダウンロードしたタイルの地図番号をそのまま付けてください。

> **アンチエイリアスとは？**
> 選択範囲の斜めの線や曲線を選ぶと、ソフトによっては境界をぼかして「ギザギザに見えないように」自動処理することがあります。これをすると白と透明の間に半透明のピクセルができ、透明度の要件を満たさなくなって却下されます。**必ずOFF（無効）に設定してから作業**してください。設定方法は[3章「GIMPで編集する」](/docs/territory/gimp/)・[4章「Photopeaで編集する」](/docs/territory/photopea/)の手順3にあります。
{: .callout .warn}

## 条件を満たしていないと

運営botは、届いた画像を次の8つの条件で確かめます。番号は、却下されたときの投稿に出る番号です。

| 番号 | 条件 | 区分 |
|---|---|---|
| ① | 中身が正しいPNG画像である | その他の要件 |
| ② | 大きさが5000×5000ピクセルちょうど | その他の要件 |
| ③ | 透明度が、完全な不透明か完全な透明のどちらかだけ | その他の要件 |
| ④ | 面積が25万ブロック以下（いくつかのタイルにまたがるときは合計） | ルールの要件（旧ボーダー外の個人開発領に関するルール特例第3条第1項） |
| ⑤ | 特定保護区域と重ならない | ルールの要件（旧ボーダー外の個人開発領に関するルール特例第3条第2項） |
| ⑥ | 他の人の個人開発領と重ならない | ルールの要件（旧ボーダー外の個人開発領に関するルール特例第3条第3項） |
| ⑦ | ファイル名のプレイヤー名が紐づけ済み | その他の要件 |
| ⑧ | 範囲が旧ボーダー外にある | 個人開発領は旧ボーダー外に設定するもの（旧ボーダー外の個人開発領に関するルール特例第2条第1項） |

- 1つでも満たしていなければ、届出は却下されます。却下の投稿には、満たしていない条件が全部、ファイル名と数値付きで書かれます。
- 却下されても、今持っている個人開発領は変わりません。画像を直して出し直せます。
- 却下の投稿の読み方と条件ごとの直し方は、[運営botの個人開発領の章](/docs/opsbot/kaihatsu/)の「却下されたとき」にあります。
