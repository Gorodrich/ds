運営者が「運営の承認」を決めるときと、技術者のコマンドの使用などを記名で許可するときに読む章です。運営投票を始める・投票する・会議中に決める（短縮投票）・特定保護区域内の建築を承認する、の操作をまとめています。参加者は、この章のコマンドを使えませんが、運営の承認が運営側でどう決まるかの説明として読めます。

この章のコマンドとボタンは、ディスコード鯖（Discordサーバー「3DS半分こするくらい仲良しクラフト中央委員会」）にいる運営bot（OpsBot。Discord上の表示名は「DSクラフト運営bot」）のものです。Discordの入力欄に `/` を打つと候補が出ます。運営botは投票の受付と集計を代わりに行うもので、承認するかどうかは運営者の投票や許可で決まります。全体の説明は[運営bot](/docs/opsbot/)にあります。

## 対象と、実行できる人

この章の対象は運営者（ディスコード鯖で「運営」ロールを持つ人）です。この章のコマンドとボタンは、すべて運営者だけが使えます。

| 操作 | すること | 実行できる人 |
|---|---|---|
| `/modvote start` | 運営投票を始める | 運営者だけ |
| `/modvote quick` | 会議中に短縮投票を始める | 運営者だけ |
| `/modvote hogokuiki_build` | 特定保護区域内の建築・採掘を承認するための運営投票を始める | 運営者だけ |
| 運営投票の「賛成」「反対」「棄権」ボタン | 運営投票で投票する | 運営者だけ |
| `/modvote status` | 運営投票の状況を確かめる | 運営者だけ |
| `/kyoka` | 記名式の許可を求める（要請する） | 運営者だけ |
| 記名式の許可の「OK」「NG」ボタン | 要請を許可する・許可しない | 運営者だけ |

参加者は、運営投票に参加できず、これらのコマンドも使えません。参加者が投票するのは参加者投票で、[参加者投票](/docs/opsbot/vote/)の章にあります。

運営投票の要点：運営者は投稿の「賛成」「反対」「棄権」のボタンで投票します。期限は別に定めがない限り投票を始めてから24時間後で、棄権した人を除いた運営者の過半数の賛成で承認されます。運営者1人の判断では、運営の承認になりません。くわしくは下の「運営投票とは」にあります。

## 参加者の方へ：運営の承認が要ることをしたいとき

ルールで「運営の承認」が要るとされていることを参加者がしたいときは、チケットで運営に求めます。たとえば、特定保護区域の中で建築・採掘をするには、前もって運営の承認を得なければなりません（禁止事項及び罰則に関するルール第12条第1項）。求め方は[普段の生活でできること](/docs/life/daily/)の 4-3、チケットの出し方は[困ったときは](/docs/life/help/)にあります。

チケットを受けた運営者が、この章のコマンドで運営投票を始めます。承認されるまで、その行為を始めてはいけません。

## 運営投票とは

ルールで「運営の承認」が要るとされている事柄は、運営者の秘密投票で決まります。この投票を運営投票といいます（基本ルール第2条第1項、基本ルール第2条第2項）。運営者1人の判断では、運営の承認になりません。

- **期限**：別に定めがない限り、投票を始めてから24時間後です（基本ルール第2条第2項）。
- **棄権**：期限までに投票しなかった運営者は、その投票を棄権したものとみなされます（基本ルール第2条第3項）。
- **承認に必要な賛成**：別に定めがない限り、棄権した人を除いた運営者（運営投票者）の過半数の賛成です（基本ルール第2条第4項）。賛成した人の数が、賛成と反対を合わせた数の半分を超えたときに承認されます。賛成と反対が同じ数のときは、承認されません。

別に定めがある事柄は、その定めに従います（下の「承認事項と、ルールが求める賛成」の表）。運営投票のしくみとルール改正の流れは[ルール改正・運営制度について](/docs/life/amendments/)の 11-4 にもまとめています。

## 運営投票を始める（`/modvote start`）

運営の承認が要る事柄が出たら、運営者は `/modvote start` で運営投票を始めます。期限は投票を始めてから24時間後で、期限が来ると運営botが自動で締め切ります。

| オプション | 入れるもの |
|---|---|
| `approval_key`（必須） | 何についての承認か。下の表から選ぶ |
| `subject`（必須） | 件名・案件の内容 |
| `target` | 対象の運営者。運営者の処罰・解任と再任では必ず入れる |

### 承認事項と、ルールが求める賛成

`approval_key` で選べる事柄と、それぞれの根拠の条、ルールが求める賛成は次のとおりです。運営botは、選んだ事柄に合わせて票を数えます。

| 選択肢 | 根拠 | ルールが求める賛成 |
|---|---|---|
| 処罰の決定・執行 | 禁止事項及び罰則に関するルール第16条 | 運営投票者の過半数 |
| 恩赦 | 禁止事項及び罰則に関するルール第22条 | 運営投票者の過半数 |
| 特定保護区域の設定 | 基本ルール第21条 | 運営投票者の過半数 |
| 情報の不開示決定 | 基本ルール第22条第2項 | 運営投票者の過半数 |
| 参加審査後の可否 | 基本ルール第5条の3第4項 | 運営投票者の過半数 |
| 領土の譲渡の承認 | 国家に関するルール第4条第2項 | 運営投票者の過半数 |
| 国家の公認・公認取消 | 基本ルール第10条第1項、国家に関するルール第1条第2項、基本ルール第28条第2項 | 運営投票者の過半数 |
| ルールの制定・改正（特別多数） | 基本ルール第28条第1項 | 運営投票者の3分の2以上 |
| ワールドデータの外部利用（参加者限定） | 基本ルール第4条第3項 | 運営投票者の過半数 |
| ワールドデータの外部利用（非参加者含む・特別多数） | 基本ルール第4条第4項 | 運営者の総数の3分の2以上 |
| 運営者の処罰・解任（本人除く全会一致・target必須） | 基本ルール第26条第1項、基本ルール第13条 | 対象の運営者を除くすべての運営者 |
| 運営者の再任（本人除く全会一致・target必須） | 基本ルール第12条第2項 | 対象の運営者を除くすべての運営者 |
| その他（分類表にない事項・通常多数決） | 基本ルール第2条第4項 | 運営投票者の過半数 |

- 「運営投票者の過半数」は、棄権した人を除いた運営者の過半数です（基本ルール第2条第4項）。「運営者の総数の3分の2以上」は、棄権した人や投票しなかった人も数に入るので、賛成しなかった人と同じ扱いになります（基本ルール第4条第4項）。
- 運営者の処罰・解任と再任では、`target` に対象の運営者を入れます。対象の運営者は投票の数から外れ、その人を除くすべての運営者の賛成が要ります（基本ルール第26条第1項、基本ルール第13条、基本ルール第12条第2項）。
- ルールの制定・改正と、ワールドデータの外部利用には、運営の承認のほかに参加者の承認も要ります（基本ルール第28条第1項、基本ルール第4条第3項、基本ルール第4条第4項）。参加者の承認は、別に参加者投票で決めます。運営者の操作は[参加者投票](/docs/opsbot/vote/)の章の「運営者の操作」にあります。

## 投票する（ボタンを押す）

1. 運営投票が始まると、運営botが運営投票の専用チャンネル（投票場）にメッセージを投稿します。
2. そのメッセージの「賛成」「反対」「棄権」のどれかのボタンを押します。
3. 押した結果は、自分にだけ見えるメッセージで返ってきます。これで投票は終わりです。
{: .steps}

締切のあと、運営botが票を集計して結果を投稿します。締切の処理は10分おきに行われるため、結果の投稿は締切の時刻から最大10分ほど遅れます。故障ではありません。

### 秘密投票なので、誰が何に投票したかは分からない

運営投票は秘密投票です（基本ルール第2条第1項）。

- ボタンを押した結果は自分にだけ表示され、ほかの運営者には見えません。
- 誰が「賛成」「反対」のどちらに投票したかは、運営botの記録にも残りません。集計が終わると、一人ひとりの票は消されます。
- 誰が投票したか（投票したという事実）だけは、期限までに投票しなかった人を棄権として扱うために記録されます。

### 休暇中の運営者と、サブアカウント

- **休暇中の運営者**：休暇を取った運営者は、その期間、運営の職権を使えません（基本ルール第14条第2項）。運営botでは、`/staff leave` で休暇を登録している運営者を、運営投票の母数（数える人の全体）から外します。休暇の登録のしかたは[運営の仕事の管理](/docs/opsbot/task/)にあります。
- **サブアカウント**：サブアカウントは、どの投票にも参加できません（基本ルール第6条第3項）。運営投票の票は、「運営」ロールを持つ自分のアカウント（メイン垢）で入れてください。

## 特定保護区域内の建築・採掘を承認する（`/modvote hogokuiki_build`）

特定保護区域
: 運営が、参加者の一部に建築・採掘などの利益を独占されるおそれがあると判断して、運営の承認により設定する領域です（基本ルール第21条）。

特定保護区域の中で建築・採掘をするには、前もって運営の承認を得なければなりません（禁止事項及び罰則に関するルール第12条第1項）。参加者からチケットで承認を求められたら、運営者は `/modvote hogokuiki_build` で運営投票を始めます。

| オプション | 入れるもの |
|---|---|
| `area_name`（必須） | 対象の特定保護区域の名前 |
| `description` | 建築・採掘の内容の説明 |
| `area_image` | 対象の範囲を示す画像 |

このコマンドは、承認事項を「特定保護区域内の建築・採掘の承認」に決めた `/modvote start` と同じです。期限・棄権・承認に必要な賛成も、ふつうの運営投票と同じです（基本ルール第2条第2項、基本ルール第2条第3項、基本ルール第2条第4項）。

特定保護区域を新しく設定するときは、`/modvote start` で「特定保護区域の設定」を選びます（基本ルール第21条）。

## 会議中に決める（短縮投票、`/modvote quick`）

運営者がボイスチャットなどで同時に集まる会議（同時会議）の中では、24時間を待たずに決める「短縮投票」ができます（基本ルール第2条の2第1項）。

- **始められるとき**：同時会議に参加しているすべての運営者が、短縮投票をすることに同意したときだけです。1人でも同意しなければ、短縮投票はできません（基本ルール第2条の2第1項）。
- **進め方**：同意があればすぐに運営投票を始め、その同時会議が続いているあいだに投票を終えます（基本ルール第2条の2第1項）。短縮投票も、運営者の秘密投票です（基本ルール第2条の2第2項）。
- **承認に必要な賛成**：投票が終わるときまでに、はっきり棄権すると示した運営者を除いた、運営者の総数の過半数の賛成が要ります（基本ルール第2条の2第3項）。会議に出ていない運営者や、投票しなかった運営者も、棄権を示していなければ数に入るので、賛成しなかった人と同じ扱いになります。ただし、別に定めがある事柄は、その定めに従います（基本ルール第2条の2第3項）。

短縮投票を始める運営者は、会議に参加しているすべての運営者が同意したことを、自分で確かめてから `/modvote quick` を実行します。運営botは、全員が同意したかどうかを確かめられません。

オプション（`approval_key`・`subject`・`target`）は `/modvote start` と同じです。短縮投票の期限は、会議中に終えられるよう24時間より短く設定されていて、期限が来ると運営botが自動で締め切ります。投票のしかたは、ふつうの運営投票と同じボタンです。

## 投票の状況を確かめる（`/modvote status`）

運営投票の状況は、`/modvote status` で確かめられます。

- `vote_id` を入れずに実行すると、進行中の運営投票が一覧で表示されます。
- 特定の投票を見たいときは、`vote_id` に投票のIDを入れます。入力中に件名で候補が出るので、そこから選べます。例：`/modvote status vote_id:<投票のID>`

## 記名で許可する（`/kyoka`）

`/kyoka` は、運営者に記名式の許可を求めるコマンドです。記名式の許可では、誰が「OK」や「NG」を押したかが、運営者の名前つきで記録されます。運営投票のような秘密投票とは違い、誰が許可したかは伏せられません。

### 技術者がコマンドを使うときのルール

技術者
: マイクラ鯖でオペレーター権限を持つ人です（基本ルール第1条第7号）。技術者は、運営者で、ディスコード鯖で「技術部門」ロールを付けられた人でなければなりません（基本ルール第23条）。

技術者がマイクラ鯖でコマンドを使ったり、クリエイティブモードに変えてその権限を使ったりできるのは、次のときだけです（基本ルール第24条）。

1. 参加者の不利益をなくすために必要なとき
2. 参加者の利益を増やすために必要で、3人以上の運営者及び参加者の承認を得たとき
3. 公共施設を建てるために必要なとき
4. メンテナンスのために必要なとき
5. ルール違反者の行動を調べるために必要なとき

`/kyoka` で今選べる種別は「技術者のコマンド使用（利益増進目的）」だけで、上の2つ目のときに使います。`/kyoka` を使えるのは運営者だけで、参加者は使えません。参加者が、自分たちの利益のために技術者のコマンドを使ってほしいときは、チケットで運営に相談してください（[困ったときは](/docs/life/help/)）。

### 許可を求める・許可する

| オプション | 入れるもの |
|---|---|
| `kind`（必須） | 許可の種別。今は「技術者のコマンド使用（利益増進目的）」だけ |
| `subject`（必須） | 件名・案件の内容 |
| `description` | 補足の説明 |

1. 運営者が `/kyoka` を実行すると、要請が運営専用のチャンネルに投稿されます。投稿には「OK」「NG」「取り下げ」のボタンが付いています。
2. 運営者が「OK」または「NG」を押します。押せるのは、「運営」ロールを持つ人だけです。
3. 許可が成立すると、要請した運営者にDMで知らせが届きます。
{: .steps}

- 誰が・いつボタンを押したかは、運営者の名前とともに記録され、あとから消えません。
- 要請を取り下げられるのは、要請した本人だけです。
- 休暇を登録している運営者は、記名式の許可の母数からも外れます。運営サブ垢（運営者の2つ目のアカウント）を運営botに連携しているときは、サブ垢で押しても、メイン垢が押したものとして数えます（[運営の仕事の管理](/docs/opsbot/task/)の「運営サブ垢を連携する」）。

海の埋立ての許可も同じ記名式の許可ですが、参加者が `/umetate` で求めます。[海の埋立ての許可](/docs/opsbot/umetate/)の章にあります。
