運営者が、マイクラ鯖などに障害（思いがけない停止や不具合）が起きたときにお知らせを出すとき、運営botの動きを確かめたり一部を止めたりするときに読む章です。参加者は、障害のお知らせの読み方を知りたいときに読めます。

この章のコマンドは、ディスコード鯖（Discordサーバー「3DS半分こするくらい仲良しクラフト中央委員会」）にいる運営bot（OpsBot。Discord上の表示名は「DSクラフト運営bot」）のスラッシュコマンドです。Discordの入力欄に `/` を打つと候補が出ます。運営botはお知らせの文面を決まった形に整えて投稿するもので、障害が起きたかどうかを判断し、お知らせを出すのは運営者です。全体の説明は[運営bot](/docs/opsbot/)にあります。

## 対象と、コマンドを実行できる人

この章の対象は運営者（ディスコード鯖で「運営」ロールを持つ人）です。この章のコマンドは、すべて運営者だけが実行できます。参加者・仮参加者は実行できません。

| コマンド | すること | 実行できる人 |
|---|---|---|
| `/shogai start` | 障害の第1報を出す | 運営者 |
| `/shogai update` | 障害の続報を出す | 運営者 |
| `/shogai resolve` | 障害の復旧報を出す | 運営者 |
| `/ops cost`・`log`・`dashboard`・`llm` | 運営botの利用状況・操作記録の確認、ダッシュボードの更新、自動判定機能の一時停止と再開 | 運営者 |

運営サブ垢（運営者が運営の仕事に使うために連携したサブアカウント）からも実行できます。連携のしかたは[運営の仕事の管理](/docs/opsbot/task/)にあります。

マイクラ鯖に入れない、障害のあとにワールドに異常を見つけた、というときは、参加者はこれらのコマンドではなくチケットで運営に知らせます。確かめる順番は[困ったときは](/docs/life/help/)の 12-4・12-5 にあります。

## メンテナンスと、参加者への告知のルール

運営者は、マイクラ鯖とディスコード鯖を適正に管理するために、メンテナンスを行うことができます。このとき、運営者は参加者の権利を一時的に制限することができます（基本ルール第15条第1項）。マイクラ鯖を止めて参加できなくすることなどが、これに当たります。

メンテナンスで参加者の権利を制限したとき、運営者は、遅滞なくそのことを参加者に告知しなければなりません。制限の必要がなくなったら、すぐに制限を解かなければなりません（基本ルール第15条第2項）。

参加者は、マイクラ鯖に参加する権利を持っています。ただし、メンテナンス、緊急停止、不具合などでマイクラ鯖が止まっている間は、参加する権利はありません（基本ルール第7条第2号）。障害でマイクラ鯖に入れなかったことは、参加する権利の侵害にはあたりません。

メンテナンスの開始と終了は、「鯖お知らせ」チャンネルに自動で投稿されます。障害が起きたときは、運営者が `/shogai` で「鯖お知らせ」チャンネルにお知らせを出します。

## 参加者向け：障害のお知らせの読み方

障害のお知らせは、第1報 → 続報（第2報、第3報…） → 復旧報の順に「鯖お知らせ」チャンネルに出ます。どのお知らせも、見出しが「（何が）障害（今の状態）」の形になっています。

| お知らせ | いつ出るか | 書かれていること |
|---|---|---|
| 第1報 | 障害が分かったとき | 発生日時、影響範囲（どのサービスがどうなっているか）、原因、復旧の見込み、ワールドデータへの影響、次のお知らせをいつ出すか |
| 続報（第N報） | 状況が変わったとき、または前のお知らせで予告した時刻 | 第1報と同じ項目の、その時点の内容 |
| 復旧報 | 直ったとき | 復旧日時、発生から復旧までにかかった時間、影響範囲（「復旧済み」）、経緯、補填の有無、ワールドを巻き戻した場合はどの時点まで戻したか |

- 次のお知らせの時刻が書かれていれば、その時刻までに続報が出ます。その前に直ったときは、復旧報が出ます。時刻が書かれていないときは、状況が変わりしだい続報が出ます。
- お知らせは投稿したあとに書き直されません。前のお知らせに誤りがあったときは、次のお知らせで訂正されます。
- 第1報と復旧報のときは、「お知らせ」チャンネルにも短いお知らせが出ます。マイクラ鯖に入れない障害のときは、全員あての通知（@everyone）が付いた【重要】のお知らせになります。マイクラ鯖に入れる障害（Dynmapなど一部のサービスだけの障害）のときは、全員あての通知は付かず、マイクラ鯖などほかのサービスはいつもどおり使えることが書かれます。

障害が直ったあとは、マイクラ鯖に入ったときに自分の建築物やアイテムに異常がないかを確かめてください。異常を見つけたら、復旧報（補填と巻き戻しの内容）を確かめたうえで、チケットで運営に知らせます（[困ったときは](/docs/life/help/)の 12-5）。

## 第1報を出す（`/shogai start`）

障害が分かったら、運営者が `/shogai start` で第1報を出します。運営botは障害を見つけたり判断したりしません。障害かどうかを判断して第1報を出すのは運営者です。

| オプション | 入れるもの |
|---|---|
| `subject` | 何が止まっているか（例：Minecraftサーバー）。見出しの「◯◯障害」になる（必須） |
| `status` | 今の状態（例：サーバー停止中）。見出しの括弧の中になる（必須） |
| `minecraft_down` | マイクラ鯖に入れない障害か（必須）。`True` にすると、「お知らせ」チャンネルの短いお知らせが @everyone 付きの【重要】になる |
| `started_at` | 発生日時。入れなければ今の時刻 |
| `next` | 次のお知らせの時刻。入れなければ「状況に変化があり次第お知らせします。」になる |
| `cause_short` | 「お知らせ」チャンネル向けの、原因の短い言い方（例：停電）。入れなければ「原因を調査中の障害」になる |
| `resume_eta` | 「お知らせ」チャンネル向けの、再開の見込み。入れなければ「未定」になる |
| `world_data` | 「お知らせ」チャンネル向けの、ワールドデータの状態（「無事を確認済み」か「調査中」）。入れなければ「調査中」になる |
| `announce` | 「お知らせ」チャンネルにも投稿するか。入れなければ投稿する |

実行すると入力欄が開くので、冒頭の文、影響範囲、原因、復旧の見込み、データへの影響を書いて投稿します。

- 影響範囲は「- サービス名：状態」の箇条書きで書きます。復旧報で「復旧済み」に置き換わるのは、この形で書いた行です。
- 日時は「14:05」や「10/8 14:05」の形で入れます（全角の数字でもかまいません）。日付を省くと今日の日付になり、それが今より先の時刻になるときは前の日として扱われます。
- `next` に「16:00」のように時刻だけを入れると、「16:00までに第2報を出します（それまでに復旧した場合は復旧時にお知らせします）。」の文になります。
- 投稿したお知らせはあとから書き直せません。誤りは次の報で訂正します。

## 続報を出す（`/shogai update`）

状況が変わったとき、または予告した時刻になったときは、`/shogai update` で続報を出します。第何報かの番号は自動で付きます。入力欄は前のお知らせの内容が入った状態で開くので、変わったところだけを直して投稿します。続報のときは、「お知らせ」チャンネルには投稿されません。

| オプション | 入れるもの |
|---|---|
| `incident` | どの障害の続報か。続いている障害が1つだけなら入れなくてよい（2つ以上あるときは候補から選ぶ） |
| `status` | 今の状態。入れなければ前のお知らせと同じ見出しになる |
| `next` | 次のお知らせの時刻 |

## 復旧報を出す（`/shogai resolve`）

直ったら、`/shogai resolve` で復旧報を出します。入力欄は、影響範囲の「停止中」などが「復旧済み」に置き換わり、経緯に「発生」「復旧確認」の2行が入った状態で開きます。冒頭の文と、発生から復旧までにかかった時間は自動で入ります。

| オプション | 入れるもの |
|---|---|
| `incident` | どの障害の復旧報か。続いている障害が1つだけなら入れなくてよい |
| `resolved_at` | 復旧日時。入れなければ今の時刻 |
| `compensation` | 補填。入れなければ「なし」になる |
| `status` | 見出しの括弧の中。入れなければ「全サービス復旧」になる |
| `rollback_to` | ワールドを巻き戻したときは、どの時点まで戻したか。入れなければ「影響なし」になる |
| `announce` | 「お知らせ」チャンネルにも投稿するか。入れなければ投稿する |

- 「お知らせ」チャンネルの短いお知らせは、第1報の `minecraft_down` に合わせた形（【重要】か、そうでないか）になります。障害が3時間以上続いたときは、お詫びの文に「長期間にわたり」が付きます。
- 「鯖お知らせ」チャンネルへの投稿はできて、「お知らせ」チャンネルへの投稿だけができなかったときは、実行した運営者に「手動で投稿してください」と表示されます。そのときは、運営者が「お知らせ」チャンネルに自分で投稿します。

## 運営者だけが使う管理用のコマンド（`/ops`）

`/ops` は、運営botがきちんと動いているかを運営者が確かめ、必要なときに一部を止めるためのコマンドです。参加者の手続きや、運営投票などの結果を変えるものではありません。

| サブコマンド | すること |
|---|---|
| `/ops cost` | 自動判定機能（チケットの内容の要約など、決まった手順では判定しにくいことを扱う機能）を呼び出した件数などの利用状況を見る |
| `/ops log` | 操作の記録（承認・却下・撤回、紐づけの変更など、運営botで行った操作の記録）を新しい順に見る。`limit` で件数（入れなければ20件、最大50件）、`actor` で操作した人を絞り込める |
| `/ops dashboard` | ダッシュボード（運営botがチャンネルに出している、状況をまとめたメッセージ）を更新する。`action` で「即時更新」か「再投稿」を選ぶ（必須） |
| `/ops llm` | 自動判定機能の状態を見る、一時停止する、再開する。`action` で「状態確認」「一時停止」「再開」を選ぶ（入れなければ状態確認だけ） |

- ダッシュボードの「即時更新」は、今あるメッセージを、自動の更新を待たずにすぐ新しくします。「再投稿」は、運営向けのダッシュボードを次の更新のときに新しいメッセージとして出し直します。ほかの知らせに埋もれて見つけにくくなったときに使います。古いメッセージは消えずに残ります。
- 自動判定機能を一時停止しても、運営botのほかの機能（個人開発領の届出、投票、許可、タスクの督促など）は止まらずに動きます。自動判定機能の呼び出しが続けて失敗したときは、自動で一時停止になります。そのときは原因を確かめてから、`/ops llm` の「再開」で戻します。

運営botは、自分の処理がうまく進まないとき（毎日のホワイトリストの照合がうまくいかなかった、食い違いが見つかった、処理が滞っている、自動判定機能が自動で止まった、など）に、運営者向けに自動で知らせを出します。知らせが来たら、運営者が原因を確かめて直します。
