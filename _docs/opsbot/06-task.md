運営者が、運営の仕事（タスク）を割り振る・片付けるとき、休暇に入る・戻るとき、自分のサブアカウントを運営の仕事に使えるようにするときに読む章です。参加者は使えませんが、運営がどうやって仕事を分担し、期限を守っているかを知りたいときに読めます。

この章のコマンドは、ディスコード鯖（Discordサーバー「3DS半分こするくらい仲良しクラフト中央委員会」）にいる運営bot（OpsBot。Discord上の表示名は「DSクラフト運営bot」）のスラッシュコマンドです。Discordの入力欄に `/` を打つと候補が出ます。運営botはタスクの記録・担当者の割り当て・期限の管理・督促（期限を過ぎたときの催促）といった決まった作業を代わりに行うもので、仕事そのものをするのも、承認するかどうかを決めるのも運営者です。全体の説明は[運営bot](/docs/opsbot/)にあります。

## 対象と、コマンドを実行できる人

この章の対象は運営者（ディスコード鯖で「運営」ロールを持つ人）です。この章のコマンドは、すべて運営者だけが実行できます。参加者・仮参加者は実行できません。

| コマンド | すること | 実行できる人 |
|---|---|---|
| `/task add` | タスクを登録する | 運営者 |
| `/task done` | タスクを完了にする | 運営者（共同確認のタスクは、担当者と共同確認者だけ） |
| `/task decline` | 自分に割り当てられたタスクを辞退する | そのタスクの担当者本人だけ |
| `/task hold` | 自分に割り当てられたタスクを保留にする | そのタスクの担当者本人だけ |
| `/task list` | 自分に残っているタスクと期限を見る | 運営者 |
| `/staff leave` | 自分の休暇を登録する・解除する | 運営者（自分の休暇だけ） |
| `/subaccount link`・`unlink`・`list` | 運営サブ垢を連携する・解除する・一覧を見る | 運営者（メイン垢から実行する） |

参加者が運営の仕事を頼みたいとき、問い合わせたいときは、これらのコマンドではなくチケットを使います（[困ったときは](/docs/life/help/)）。

## タスクを登録する（`/task add`）

運営内でだれかが片付けなければならない仕事が出てきたら、`/task add` で登録します。`title`（タスク名）だけが必須です。

| オプション | 入れるもの |
|---|---|
| `title` | タスク名（必須） |
| `summary` | 詳しい内容 |
| `assignee` | 担当者。入れなければ運営botが自動で選ぶ |
| `priority` | 優先度（高・中・低。入れなければ中） |
| `tag_1`〜`tag_3` | そのタスクに必要な分野（下の表から3つまで） |
| `requires_technician` | 技術者（マイクラ鯖でオペレーター権限を持つ人）だけに任せるタスクか |
| `requires_developer` | 管理者・開発者だけに任せるタスクか（サーバーの設備や運営botの設定を変える仕事など） |
| `required_permission_tier` | 必要な実行権限のレベル（`admin`・`broad`・`standard`） |
| `controversial` | 意見が割れやすいタスクか。付けると共同確認者が自動で付く（下の「タスクを完了にする」） |
| `estimated_load` | 想定される手間（1〜5） |
| `due_at` | 期限。日本時間で `YYYY-MM-DD-hh-mm` の形（例：`2026-09-10-18-30`）。入れなければ運営botが決めた目標の期限になる |

`tag_1`〜`tag_3` で選べる分野は、次の9つです。

| タグ | 分野 |
|---|---|
| `rule_drafting` | ルールの起草・改正案の検討 |
| `technical` | マイクラ鯖の技術的な対応（プラグインの導入、サーバーの設定、障害の対応など） |
| `participant_support` | 参加者からの問い合わせ・個別の対応 |
| `moderation` | 処分・紛争の対応 |
| `community_management` | コミュニティの雰囲気づくり、雑談鯖などの運営 |
| `announcement` | 告知文・周知の文書の作成 |
| `survey` | 情報収集・調査・資料の整理 |
| `controversial_review` | 意見が割れやすい、または外部との火種になりうる議題の最初の検討 |
| `data_handling` | ワールドデータなど、取り扱いに注意が要る情報を扱う仕事 |

### 担当者の決まり方

`assignee` を入れなかったときは、運営botが担当者を自動で選び、選ばれた運営者にDMで知らせます。

- まず、休暇中でないこと、技術者に限るタスクなら技術者であること、必要な実行権限を持っていること、抱えているタスクが上限に達していないこと、などの条件で候補を絞ります。
- 残った候補から、タスクの分野と得意分野の合い方、手の空き具合、これまでの完了の実績、ふだん活動している時間帯などをもとに選びます。同じ人に続けて割り当たりすぎないようにもします。
- 決めきれないときや、条件に合う人がいないときは、運営専用のチャンネルに「要手動対応」の知らせが出て、運営者が手動で担当者を決めることになります。

## 自分のタスクを確かめる（`/task list`）

`/task list` で、自分に残っている未完了のタスクと、その期限を見られます。結果は自分にだけ表示されます。

`/task done`・`decline`・`hold` の `task_id` は、タスク名の一部を打つと候補が出ます。候補は「タスク名（#番号）」の形で表示されます。`decline`・`hold` の候補に出るのは、自分に割り当てられたタスクだけです。

## 期限と督促

タスクには期限があります。期限を過ぎても完了にならないと、運営botが段階を追って督促します。

1. 担当者にDMで知らせます。
2. 運営専用のチャンネルで担当者をメンションします。
3. 運営者全体に共有します。
4. 別の運営者に自動で割り当て直します。
{: .steps}

各段階に進むまでの時間は運営botの設定で決まっています。督促を送らない時間帯も設定されています。

期限までに片付けられないと分かったときは、督促を待たずに、下の「辞退する」か「保留にする」を使ってください。

## タスクを完了にする（`/task done`）

仕事が終わったら、`/task done` で `task_id`（タスク）と `evidence`（完了の根拠）を入れて完了にします。`evidence` は必須で、仕事の結果が分かるメッセージのリンクなどを入れます。

例：`/task done task_id:<タスク> evidence:<結果を投稿したメッセージのリンク>`

### 共同確認のタスク

`controversial` を付けて登録したタスクなど、意見が割れやすいタスクには、担当者のほかに次点の候補者が共同確認者として自動で付きます。共同確認のタスクは、担当者と共同確認者の2人ともが `/task done` をして、はじめて完了になります。1人だけが完了にした状態では「もう一方待ち」として残ります。

共同確認のタスクを完了にできるのは、担当者と共同確認者だけです。ほかの運営者は完了にできません。

## 辞退する（`/task decline`）

割り当てられたタスクを引き受けられないときは、`/task decline` で辞退します。理由は要りません。辞退できるのは、そのタスクの担当者本人だけです。自分がすでに完了の操作をしたタスクは辞退できません。

辞退すると、運営botが次の候補の運営者に自動で割り当て直します。辞退した人は、そのときの候補から外れます。割り当て直せる人がいないときは、運営専用のチャンネルに手動での対応を求める知らせが出ます。

## 保留にする（`/task hold`）

今は進められないが、あとで再開するタスクは、`/task hold` で保留にします。`resume_at`（再開する予定の日。`YYYY-MM-DD` の形）が必須で、`reason`（保留の理由）は任意です。保留にできるのは、そのタスクの担当者本人だけです。

例：`/task hold task_id:<タスク> resume_at:<再開予定日> reason:<理由>`

再開の予定日になると、タスクは自動で「割当済」に戻ります（運営botの処理は10分おきなので、最大10分ほど遅れます）。

## 運営botが自動で登録するタスク

次のときは、運営者が `/task add` をしなくても、運営botが自動でタスクを登録します。

- 個人開発領の届出で、運営botの承認を運営者が撤回したとき：運営の審査（運営投票）に切り替えるタスクが登録されます（[個人開発領の届出](/docs/opsbot/kaihatsu/)の「運営者の操作」）。
- 個人開発領の届出の画像の処理がくり返し失敗したとき：運営専用のチャンネルに「【要対応】」の投稿が出て、優先度「高」のタスクが登録されます。

## 休暇を取る・戻る（`/staff leave`）

### ルールの決まり

運営者は、やむを得ない事情で一時的に運営者の仕事を続けられなくなったとき、他の運営者に期間を示して伝えることで、その期間、休暇を取れます（基本ルール第14条第1項）。

休暇を取った運営者は、その期間、運営の職権を使えません（基本ルール第14条第2項）。休暇中の運営者は、運営投票や記名式の許可（海の埋立ての許可など）で、運営として判断することができません。ルールのしくみは[ルール改正・運営制度について](/docs/life/amendments/)の「11-6. 運営者が休暇を取るとき」にもまとめています。

### 運営botへの登録

休暇に入るときは、他の運営者に期間を示して伝え、`/staff leave` で休暇を登録します。

- 休暇に入る：`/staff leave action:start until:<復帰予定日>`。`until` は `YYYY-MM-DD` の形で、`action:start` のときは必須です。
- 休暇を終える：`/staff leave action:end`。すぐに解除されます。

登録できるのは自分の休暇だけです。他の運営者の休暇を代わりに登録することはできません。

休暇を登録している間、運営botは次のように扱います。

- 運営投票の母数（数える人の全体）と、記名式の許可の母数から外します。
- タスクの担当者を自動で選ぶときの候補から外します。

休暇は運営者のための制度です。参加者投票の母数には関係しません。

## 運営サブ垢を連携する（`/subaccount`）

### サブアカウントのルール

参加者は、自分が持っているDiscordアカウントのうち、ディスコード鯖で「人民」ロールが付いていないもの（サブアカウント）をディスコード鯖に参加させるよう、運営に求めることができます（基本ルール第6条第1項）。運営は、求めがあれば速やかに招待し、参加したら「サブ垢」ロールを付けます。ただし、サブアカウントを使ってルールに違反するおそれがあると判断するだけの相当の理由があるときは、この限りではありません（基本ルール第6条第2項）。

サブアカウントは、どの投票にも参加できません（基本ルール第6条第3項）。参加者投票にも運営投票にも、票はメイン垢（「人民」ロール・「運営」ロールを持つ本人のアカウント）で入れます。サブアカウントの求め方などは[ディスコード鯖での注意点](/docs/life/discord/)にあります。

### 運営サブ垢とは

運営サブ垢は、運営者が自分のサブアカウントから運営botの運営者向けのコマンドを使えるようにするしくみです。「運営サブ垢」ロールは「運営」ロールとも「サブ垢」ロールとも別のロールで、運営が手作業で付けます。

「サブ垢」ロールだけのアカウントで `/authorise` を実行できないこと（[アカウントの紐づけ](/docs/opsbot/authorise/)）とは別の話です。運営サブ垢を連携しても、そのアカウントでMinecraftのアカウントを紐づけられるようにはなりません。

### 連携のしかた

1. サブアカウントに「運営サブ垢」ロールが付いていることを確かめます。付いていないと連携できません。
2. メイン垢（「運営」ロールを持つ自分のアカウント）から `/subaccount link user:<サブアカウント>` を実行します。
3. サブアカウントに運営botから本人確認のDMが届きます。サブアカウントで、24時間以内に許可のボタンを押します。
4. 許可のボタンを押すと、連携が成立します。
{: .steps}

24時間以内に許可しなかったときは、連携の求めは無効になります。もう一度 `/subaccount link` からやり直します。

- 連携を解除する：メイン垢から `/subaccount unlink user:<サブアカウント>`。解除できるのは、そのサブアカウントを連携したメイン垢だけです。
- 連携の一覧を見る：メイン垢から `/subaccount list`。連携済みのものと、本人確認の待ちのものが分かります。

1つのメイン垢に、いくつかのサブアカウントを連携できます。1つのサブアカウントを連携できるメイン垢は1つだけで、他の運営者が連携済み、または本人確認の待ちのサブアカウントは指定できません。

### 連携したあと

連携したサブアカウントで運営者向けのコマンドを使うと、運営botはメイン垢が行ったものとして扱い、記録にもメイン垢の名前が残ります。記名式の許可（海の埋立ての許可など）のボタンも、メイン垢が押したものとして数えます（[海の埋立ての許可](/docs/opsbot/umetate/)の「運営者の操作」）。同じ人がメイン垢とサブアカウントで2人ぶんに数えられることはありません。

連携していない、または本人確認が済んでいないサブアカウントで運営者向けのコマンドを使うと、運営botは受け付けず、先に連携をするよう表示します。

運営投票の票は、メイン垢で入れてください。サブアカウントは、どの投票にも参加できません（基本ルール第6条第3項）。運営投票のしかたは[運営の承認](/docs/opsbot/modvote/)にあります。
