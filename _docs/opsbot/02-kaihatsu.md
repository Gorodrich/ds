個人開発領（旧ボーダー外に参加者が届け出て確保する、個人の開発の範囲）を、運営botの `/kaihatsu` で届け出る・変える・やめる・譲るときに読む章です。届出の結果として運営botから届いたメッセージの意味を知りたいときや、誰かから身に覚えのない確認のDMが届いたときにも読んでください。

この章のコマンドは、ディスコード鯖（Discordサーバー「3DS半分こするくらい仲良しクラフト中央委員会」）にいる運営bot（OpsBot。Discord上の表示名は「DSクラフト運営bot」）のスラッシュコマンドです。Discordの入力欄に `/` を打つと候補が出ます。運営botは受付・記録などの決まった作業を代わりに行うもので、全体の説明は[運営bot](/docs/opsbot/)にあります。

個人開発領の説明は3か所に分かれています。制度とルール（何ができるか、要件、重なったときの扱い）は[旧ボーダー外で開発したいときは（個人開発領）](/docs/life/personal-dev/)、届出に使う画像の作り方と初めての届出の手順は[個人開発領の申請](/docs/territory/)、この章は `/kaihatsu` のコマンドの全部（変更・削除・譲渡・一括申請、結果の読み方、運営の撤回）です。

## 対象と、コマンドを実行できる人

この章の対象は、個人開発領を持っている参加者と、これから届け出る参加者です。コマンドやボタンごとに、使える人が決まっています。

| コマンド・ボタン | すること | 使える人 |
|---|---|---|
| `/kaihatsu set` | 個人開発領の設定・変更（一部の削除を含む）の届出 | `/authorise` で紐づけを済ませた参加者。他の人の分を含めて出すときは、画像のファイル名に書いたプレイヤー全員が紐づけ済みであること |
| `/kaihatsu delete` | 個人開発領の全部の削除の届出 | 自分の個人開発領を消す本人。他の人の個人開発領を対象にできるのは、グループ（下の「譲る・譲ってもらう」）を使う代表者だけ |
| `/kaihatsu group_finalize` | グループの受付を締め切り、審査を始める | そのグループに最初に届け出た人（代表者）だけ |
| `/kaihatsu list` | 自分の個人開発領の登録状況を見る | 誰でも |
| 本人確認のボタン（「この内容で申請する」「取り下げる」） | 他の人が出した届出に、自分の分が含まれているときの確認 | DMを受け取った本人だけ |
| 「撤回する（運営者）」ボタン | 運営botの承認を撤回する | 運営者（「運営」ロールを持つ人）だけ |

参加者が使うのは `/kaihatsu` の4つのサブコマンドと、本人確認のボタンです。承認の投稿に付く「撤回する（運営者）」ボタンは運営者だけが使えるもので、参加者が押しても撤回はされません（下の「運営者の操作」）。

## 使う前に確かめること

- **紐づけが済んでいること**：`/kaihatsu` は、`/authorise` でDiscordのアカウントとMinecraftのアカウントを紐づけていないと使えません。紐づけたMinecraftのユーザー名は `/whoami` で確かめられます（[アカウントの紐づけ](/docs/opsbot/authorise/)）。
- **画像のファイル名のプレイヤー名が、紐づけた名前と同じであること**：運営botは、誰の届出かを画像のファイル名だけで判断します。コマンドを実行した人ではありません。ファイル名は `<地図番号2桁>_<Minecraftのユーザー名>.png` の形です（[必ず確認する条件](/docs/territory/requirements/)）。
- **前の届出が終わっていること**：同じ人について、本人確認待ち・グループの受付中・判定中の届出が残っていると、新しい `/kaihatsu set` は受け付けられません。前の届出が承認か却下で終わってから出し直します。
- **運営botからのDMを受け取れること**：保留・撤回・本人確認などはDMで届きます。Discordの設定で、このサーバーのメンバーからのダイレクトメッセージを許可しておきます。本人確認は期限を過ぎると却下になるので、とくに大事です。

この章に出てくる時間（72時間・24時間）や添付できる画像の枚数は、運営botの既定の値です。運営が設定で変えることがあるので、正確な今の値がわからないときは運営に聞いてください。

## `/kaihatsu set` は毎回「全体」を送る

`/kaihatsu set` で送った画像は、その人の個人開発領の**今の全体**として扱われます。前から持っていた範囲でも、今回の画像に写っていない部分は削除になります。増やす分だけを送る仕組みではありません。広げたあとの全体も、他の人の個人開発領と重なってはいけません（旧ボーダー外の個人開発領に関するルール特例第3条第3項）。

| やりたいこと | 使うコマンド | ルール上の手続き |
|---|---|---|
| 個人開発領を新しく作る | `/kaihatsu set` で、作りたい範囲を送る | 設定の届出（旧ボーダー外の個人開発領に関するルール特例第2条） |
| 範囲を広げる・形を変える | `/kaihatsu set` で、**変更したあとの全体**を送る | 変更の届出（旧ボーダー外の個人開発領に関するルール特例第6条） |
| 範囲の一部だけを減らす | `/kaihatsu set` で、**残したい範囲だけ**を描いた全体を送る | 一部の削除の届出（旧ボーダー外の個人開発領に関するルール特例第7条） |
| 個人開発領を全部やめる | `/kaihatsu delete` | 全部の削除の届出（旧ボーダー外の個人開発領に関するルール特例第7条） |
| 今の登録を確かめる | `/kaihatsu list` | — |
| 何人かの分をまとめて出す | `/kaihatsu set` に、全員分の画像を添付する | 各人の設定・変更の届出 |
| 範囲を他の人に譲る | `/kaihatsu set`・`/kaihatsu delete` に同じ `group` を付け、`/kaihatsu group_finalize` で締め切る | 削除の届出と設定の届出を同時に出す（旧ボーダー外の個人開発領に関するルール特例第8条第2項） |

> 一部だけ減らしたいときに `/kaihatsu delete` を使わないでください。`/kaihatsu delete` は個人開発領が全部なくなります。削除された範囲は元に戻せず、取り直すには新しく届け出ることになります。その間に他の人が届け出れば、その人のものになります。
{: .callout .danger}

一部だけ減らす届出を送ったら、承認の投稿の「⚠ 削除扱いになる範囲」に、減らしたい範囲だけが出ているかを確かめます（下の「承認されたとき」）。

範囲を変える届出にも、設定するときと同じ要件と審査があります（旧ボーダー外の個人開発領に関するルール特例第6条第2項）。

## 届け出る・範囲を変える（`/kaihatsu set`）

画像の作り方は[個人開発領の申請](/docs/territory/)の手順どおりです。ここでは送り方と、送ったあとに起きることを書きます。

| オプション | 内容 |
|---|---|
| `image1` | 必須。1枚目の画像。1枚が1つの地図番号（ゾーン）に対応します |
| `image2` 〜 `image16` | 範囲がいくつかの地図番号にまたがるときの2枚目以降。同じ地図番号の画像を2枚に分けては送れません |
| `group` | 譲渡などで、届出をグループにまとめるときだけ使います（下の「譲る・譲ってもらう」）。ふだんは空のままにします |

1. ディスコード鯖で `/kaihatsu set` を選び、`image1` から順に画像を添付して送ります。自分の分の画像は、1回の `/kaihatsu set` にすべて添付します。2回に分けると、後の届出の画像だけが全体として扱われ、先に送った分は削除扱いになります。
2. 運営botから「受付しました。判定処理を開始します。」という返事が、自分にだけ見えるメッセージで届きます。これは受け付けたという知らせで、まだ承認ではありません。
3. 運営botが画像を判定し、結果を個人開発領の専用チャンネルに、届け出た人へのメンション付きで投稿します。ふつうは数十秒から数分で出ます。
{: .steps}

- 添付できる枚数の上限は運営が設定で決めています。自分の範囲の画像が上限に収まらないときは、分けて送らずに運営に相談してください。
- 自分だけの届出で、ファイル名の形が合わない画像が1枚でも混じっていると、その届出は全体が却下されます。
- 結果がなかなか出ないときは、運営botの画像の処理が止まっていることがあります（毎日朝8時ごろに十数分の定期メンテナンスがあります）。数時間たっても結果が出ないときは運営に連絡してください。処理がくり返し失敗したときは、運営botから「処理中にエラーが発生しました。運営に確認を依頼しました。」というDMが届き、運営に対応の仕事が自動で回ります。

## 結果の種類と読み方

ルールでは、運営は届出が要件を満たすかを審査し、満たしていれば設定を認めて届け出た人に知らせ、満たしていなければ却下して、その旨と理由を知らせます（旧ボーダー外の個人開発領に関するルール特例第4条）。運営botは、機械的に判定できる条件（面積・重なり・画像の形式など）をその場で判定し、結果を出します。結果は次のどれかです。

| 結果 | 届く場所 | 意味 | すること |
|---|---|---|---|
| 承認 | 専用チャンネル | 届出が認められた | 「削除扱いになる範囲」が意図どおりかを確かめる |
| 却下 | 専用チャンネル | 条件を満たしていない。今の個人開発領は変わらない | 理由を読んで直し、出し直す |
| 保留 | DM | 他の人のまだ確定していない範囲と重なっているので、待っている | 何もしなくてよい。自動で審査し直される |
| 撤回 | DM | 承認のあと、運営者が承認を取り消した | 運営の審査の結果を待つ |

### 承認されたとき

専用チャンネルに「【個人開発領：本人確認完了・正式承認】」という投稿が、確認画像付きで届きます。投稿には次の項目があります。

| 項目 | 意味 |
|---|---|
| 分類 | 届出がルール上のどの手続きにあたるか。初めてなら「設定」（旧ボーダー外の個人開発領に関するルール特例第2条）、範囲が増えていれば「変更」（旧ボーダー外の個人開発領に関するルール特例第6条）、減っていれば「一部削除」（旧ボーダー外の個人開発領に関するルール特例第7条）。増えた所と減った所の両方があれば両方が出ます |
| 申請面積 | 描いた範囲のブロック数（不透明なピクセルの数） |
| 座標（loc1・loc2） | 範囲を囲む長方形の、対角の2点。地図に表示するためのもので、範囲そのものではありません。この長方形の面積と申請面積は一致しません |
| ⚠ 削除扱いになる範囲 | 前の範囲のうち、今回の画像に入っていなかったために削除された範囲。前の範囲が減ったときだけ出ます |
| 新規追加分 | 今回新しく加わった範囲のブロック数 |

**「⚠ 削除扱いになる範囲」は必ず確かめてください。** ここに出た範囲は、もう自分の個人開発領ではありません。意図した削除でなければ、すぐに正しい全体の画像で `/kaihatsu set` を出し直します。消えた範囲がまだ誰のものにもなっていなければ、取り直せます。

承認から24時間は、運営者が承認を撤回することがあります（下の「承認が撤回されたとき」）。この撤回と24時間の期限は運営botの仕組みで、ルールの条文に定めがあるものではありません。

### 確認画像の色

承認・却下・保留のどれでも、判定の結果を色で示した確認画像が付きます。送った画像の色にかかわらず、次の3色で表示されます。

| 色 | 意味 |
|---|---|
| マゼンタ（明るい紫） | 今回届け出た範囲 |
| 赤 | 特定保護区域や他の人の個人開発領と重なっている範囲。却下の原因の場所です |
| オレンジ | 前は自分の範囲だったが、今回の画像に入っていないため削除扱いになる範囲 |

オレンジが出ていて、それが意図した削除でなければ、すぐに出し直してください。

### 却下されたとき

専用チャンネルに「【個人開発領：Bot形式審査（却下）】」という投稿が届き、満たしていない条件が**すべて**、ファイル名と数値付きで書かれます。1つ目で打ち切られないので、投稿を読めば直す所が全部わかります。

却下されても、今の個人開発領は何も変わりません。直して何度でも出し直せます。ただし、出し直した届出の順番は、出し直した時点で数えます（旧ボーダー外の個人開発領に関するルール特例第5条第3項）。最初に出した時点の順番は残りません。

運営botが確かめる条件は、ルールの要件と、その他の要件（運営botが届出を自動で処理するために必要な要件）に分かれます。

| 運営botの条件 | 根拠 | 却下されたときの直し方 |
|---|---|---|
| ④ 面積が25万ブロック以下（いくつかの地図番号にまたがるときは合計） | ルールの要件（旧ボーダー外の個人開発領に関するルール特例第3条第1項） | 範囲を減らす。離れた場所に塗り残しがないかも確かめる |
| ⑤ 特定保護区域と重ならない | ルールの要件（旧ボーダー外の個人開発領に関するルール特例第3条第2項） | 確認画像の赤い所を避けて描き直す |
| ⑥ 他の人の個人開発領と重ならない | ルールの要件（旧ボーダー外の個人開発領に関するルール特例第3条第3項） | 確認画像の赤い所を消して出し直す。配布画像のマゼンタ（他の人の個人開発領）の消し忘れが多い原因です |
| ⑧ 範囲が旧ボーダー外にある | 個人開発領は旧ボーダー外に設定するもの（旧ボーダー外の個人開発領に関するルール特例第2条第1項） | 地図番号を確かめる |
| ① 中身が正しいPNG画像である | その他の要件 | 編集ソフトからPNGで書き出し直す。拡張子を変えただけでは直りません |
| ② 大きさが5000×5000ピクセルちょうど | その他の要件 | 配布画像の大きさを変えずに書き出す。切り抜き・拡大・縮小はしない |
| ③ 透明度が、完全な不透明か完全な透明のどちらかだけ | その他の要件 | 「アンチエイリアス」「なめらかな縁」を切ってから描き直す |
| ⑦ ファイル名のプレイヤー名が紐づけ済み | その他の要件 | ファイル名を `/whoami` に出る名前に合わせる |

条件と直し方のくわしい説明は[必ず確認する条件](/docs/territory/requirements/)と[提出前のセルフチェック](/docs/territory/checklist/)にあります。

- 他の人の個人開発領と重なって却下されたときは、重なった相手のMinecraftのユーザー名が投稿に出ます。すでに設定されている個人開発領と重なる届出は、ルールでも却下されます（旧ボーダー外の個人開発領に関するルール特例第5条第1項）。その土地を使いたいときは、持ち主と話し合って譲ってもらいます（下の「譲る・譲ってもらう」）。
- 「このコマンドはご自身（…）の申請のみ受け付けます」と出たときは、ファイル名のプレイヤー名が自分の紐づけた名前と違います。
- 「不透明ピクセルが1つも存在しません」と出たときは、範囲を描いていない画像（全部が透明）を送っています。

### 保留されたとき

届け出た範囲が、他の人の「本人確認待ちの範囲」や「グループで譲渡の手続き中の範囲」と重なっているときは、却下されずに保留になります。相手の届出がまだ確定していないためです。DMで「【個人開発領：保留】」が届きます。

保留のあいだ、自分ですることはありません。相手の結果が出たら、運営botが自動で審査し直します。

- 相手の届出が確定したとき：自分の届出は却下され、DMで知らせが届きます。範囲を変えて出し直してください。
- 相手の届出が取り下げ・期限切れ・却下になったとき：自分の届出が自動で審査し直されます。このとき、届出の順番は最初に出した時点のままです。
- 同じ場所で何人かが保留になっているときは、先に届け出た人から順に審査し直されます。

まだ誰の個人開発領でもない同じ範囲に何人かが届け出たときは、届け出た順に審査し、要件を満たす最初の届出を認めます（旧ボーダー外の個人開発領に関するルール特例第5条第2項）。保留は、この順番を守るためのものです。

### 承認が撤回されたとき

運営botの承認は、機械的に判定できる条件を満たしているという確認です。届出を審査するのは運営なので（旧ボーダー外の個人開発領に関するルール特例第4条第1項）、承認から24時間は、運営者が承認を撤回することがあります。撤回や24時間の期限そのものを定めた条文はなく、運営botの仕組みです。たとえば、配布画像でもともと透明になっている場所（旧ボーダー内など、届け出られない場所）を描き足した画像は、運営botの判定を通ってしまうことがありますが、撤回の対象になります。

撤回されると、DMで「【個人開発領：撤回】」が届き、撤回した運営者の名前と理由が書かれています。

- 承認は効力を失います。
- そのあとは、運営が運営投票（運営者どうしの秘密投票）で審査します。
- 撤回されたら、同じ内容ですぐに出し直さず、運営の審査の結果を待ってください。

24時間を過ぎると、運営botの撤回のボタンは使えなくなります。

## 今の登録を確かめる（`/kaihatsu list`）

`/kaihatsu list` を実行すると、自分の個人開発領の登録状況が、自分にだけ見えるメッセージで表示されます。

- 表示されるのは、Minecraftのユーザー名、面積（ブロック数）、座標（loc1・loc2）です。
- 範囲の形は表示されません。形は[Dynmap](https://map.ds2.uk/)（ウェブで見られるサーバーの地図）で確かめます。
- 登録がないときは「…さんの個人開発領は登録されていません。」と表示されます。

## 全部やめる（`/kaihatsu delete`）

開発権者（個人開発領を設定した参加者）は、自分の個人開発領を削除するとき、その旨を届け出ます。届け出があれば、運営は速やかにその範囲の個人開発領を削除します（旧ボーダー外の個人開発領に関するルール特例第7条）。運営botでは、全部をやめるときに `/kaihatsu delete` を使います。

| オプション | 内容 |
|---|---|
| `mcuser` | 削除する個人開発領の持ち主のMinecraftのユーザー名。省くと自分の個人開発領になります。他の人を指定するときは `group` が必要です |
| `group` | 譲渡などで、届出をグループにまとめるときに使います |

1. 自分の個人開発領を全部やめるときは、オプションを付けずに `/kaihatsu delete` を実行します。
2. 確認のボタンは出ず、その場で削除されます。自分にだけ見えるメッセージで「個人開発領を削除しました（復元はできません）。」と表示され、専用チャンネルにも削除の記録が投稿されます。
{: .steps}

- 削除は元に戻せません。
- 一部だけ減らしたいときは `/kaihatsu delete` を使わず、残したい範囲だけを描いた全体を `/kaihatsu set` で送ります（上の「`/kaihatsu set` は毎回「全体」を送る」）。
- 個人開発領が登録されていないときは「削除対象の個人開発領がありません。」と表示されます。
- 他の人の個人開発領を `mcuser` で指定して `group` を付けないと、受け付けられません。本人の知らないうちに個人開発領が消されないよう、グループを通して本人に確認するためです。

## まとめ役が何人かの分をまとめて出す（代表者による一括申請）

イベントなどで、まとめ役（代表者）が何人かの分の画像を、1回の `/kaihatsu set` にまとめて添付して出せます。`group` は付けません。誰の分かは、画像のファイル名のプレイヤー名で分けられます。

1. 代表者が、全員分の画像を `/kaihatsu set` に添付して送ります。代表者には「受付しました（…名分）。」と返事が届きます。
2. 運営botが1人ずつ判定します。条件を満たした人は「仮承認」になり、専用チャンネルに投稿されます。満たさない人は却下されます。
3. 仮承認になった本人に、運営botから「【個人開発領：本人確認】」のDMが確認画像付きで届きます。
4. 本人が72時間以内に「この内容で申請する」を押すと、正式に承認されます。
5. 本人が「取り下げる」を押したとき、または72時間のあいだに何も押さなかったときは、その人の分だけが却下されます。ほかの人の分には影響しません。
{: .steps}

- 本人の確認が遅れても、届出の順番は代表者が出した時点で数えます。
- 画像のファイル名に書いたプレイヤーが `/authorise` を済ませていないと、その人の分は受け付けられません。その人に本人確認待ちや判定中の届出が残っているときも同じです。
- 1回の届出に入っている何人かの範囲が互いに重なるときは、添付した順（`image1`、`image2`…の順）に届け出たものとして扱われます。先に判定されて条件を満たした人の範囲が優先され、後の人は重なりで却下されます。
- 代表者による一括申請では、ファイル名の形が合わない画像は、知らせもなくその画像だけが無視されます。添付したのに結果に出てこないときは、まずファイル名を確かめてください。
- 承認から24時間の撤回の期間は、本人が確認して正式に承認された時点から数えます。

> **身に覚えのない「本人確認」のDMが届いたら**：誰かがあなたの分を代わりに届け出ています。心当たりがなければ「取り下げる」を押し、運営に相談してください。72時間何も押さなければ自動で却下されるので、迷ったら「この内容で申請する」を押さないでください。
{: .callout .warn}

## 譲る・譲ってもらう（同時処理グループ `group`）

開発権者は、自分の個人開発領の全部または一部を、他の参加者に譲れます。譲るときは、譲る人の削除の届出と、譲り受ける人の設定の届出を、同時に出さなければなりません（旧ボーダー外の個人開発領に関するルール特例第8条第1項・第2項）。運営botでは、2人の届出に同じ `group`（グループの名前）を付けてまとめて出し、「全部成立する」か「全部成立しない（誰の範囲も変わらない）」のどちらかになるようにします。

### グループを使わずに別々に出すと

- 譲り受ける人が先に `/kaihatsu set` を出すと、その範囲はまだ譲る人の個人開発領なので、重なりで必ず却下されます。
- 譲る人が先に `/kaihatsu delete` を出すと、削除はその場で決まり、元に戻せません。そのあと譲り受ける人の届出が面積や画像の不備で却下されると、譲る人の範囲は消えたまま、譲り受ける人は何も得られません。空いた土地を別の人に届け出られるおそれもあります。

### 手順（AさんがBさんに譲る例）

1. **グループの名前を決めます。** ほかと重ならない文字列にします（例：`jouto-<日付>-<何か>`）。前に使った名前は使い回せません。
2. **2人がそれぞれ、同じ `group` を付けて届け出ます。**
   - 譲るAさん（全部を譲るとき）：`/kaihatsu delete group:<グループの名前>`
   - 譲るAさん（一部を譲るとき）：譲ったあとに残る範囲の全体を `/kaihatsu set image1:<画像> group:<グループの名前>` で送ります
   - 譲り受けるBさん：譲り受けたあとの自分の個人開発領の全体を `/kaihatsu set image1:<画像> group:<グループの名前>` で送ります
3. **この時点では審査は始まりません。** 届出がグループにたまるだけです。運営botから「同時処理グループに追加しました。」と返事が届きます。
4. **グループに最初に届け出た人（代表者）が、`/kaihatsu group_finalize group:<グループの名前>` で受付を締め切ります。** ここで審査が始まります。締め切ったあとは、そのグループに届出を足せません。
5. **運営botが審査します。** 先に削除を当てはめてから、設定の届出を審査します。このため、Bさんの範囲は「Aさんの範囲が消えたあとの地図」で重なりを確かめられます。
6. **関係する全員に、本人確認のDMが届きます。** 削除される側のAさんには「【個人開発領：本人確認（削除）】」、設定する側には「【個人開発領：本人確認】」が届きます。全員が72時間以内に「この内容で申請する」を押すと、グループ全体が成立し、削除と設定がまとめて決まります。
{: .steps}

- 1人でも「取り下げる」を押したとき、72時間のあいだに押さなかったとき、条件を満たさなかったときは、**グループ全体が却下**されます。誰の範囲も変わらず、Aさんの範囲も消えません。
- 譲り受ける範囲が、譲る人のもとの個人開発領の中に収まっていれば、その範囲が譲る人の個人開発領と重なることを理由に却下されることはありません（旧ボーダー外の個人開発領に関するルール特例第8条第3項）。面積や特定保護区域の要件は審査されます。
- 受付を始めてから72時間以内に締め切られなかったグループは、自動で却下（失効）されます。
- 代表者が他の人をグループに加えたときは、加えられた本人にお知らせのDMが届きます。心当たりがなければ、そのDMの「取り下げる」で取り下げられます（グループ全体が却下されます）。
- グループで明け渡される予定の土地は、グループの結果が出るまで予約されています。そのあいだに第三者が同じ土地を届け出ると保留になり、グループが却下されたときは、最初に届け出た時点の順番のまま自動で審査し直されます。

`/kaihatsu group_finalize` のオプションは `group`（必須。締め切るグループの名前）だけです。存在しないグループの名前を指定すると「指定された同時処理グループが見つかりません。」、締め切ったグループなら「この同時処理グループは既に受付を締め切っています。」と表示されます。締め切った時点で、削除する予定の個人開発領がすでにないなど、つじつまが合わないことがあれば、その場でグループ全体が却下されます。

> **締め切りを忘れないでください。** グループの届出は、代表者が `/kaihatsu group_finalize` を実行するまで、何も審査されません。
{: .callout .warn}

### 一括申請とグループの違い

| | 代表者による一括申請 | 同時処理グループ（`group`） |
|---|---|---|
| 使うとき | 誰かの分を代わりにまとめて出したい | 何人かの届出を、ばらばらに成立させたくない（譲渡） |
| 届出どうしの関係 | ばらばら。1人が却下されても、ほかの人は進む | ひとまとめ。1つが却下されると全部却下 |
| `group` | 付けない | 全員が同じ名前を付ける |
| 審査が始まるとき | 送った時点 | 代表者が `/kaihatsu group_finalize` を実行した時点 |
| 本人確認 | 対象の人それぞれに72時間の確認DM | 関係する全員（削除される人を含む）に72時間の確認DM |

## 運営botから届いたメッセージの早見表

| 届いたもの | 届く場所 | 意味 | すること |
|---|---|---|---|
| 「受付しました。判定処理を開始します。」 | 自分にだけ見える返事 | 受け付けただけ。まだ承認ではない | 結果を待つ |
| 【個人開発領：本人確認完了・正式承認】 | 専用チャンネル | 承認された | 「⚠ 削除扱いになる範囲」を確かめる。24時間は撤回されることがある |
| 【個人開発領：Bot形式審査（却下）】 | 専用チャンネル | 条件を満たさず却下。今の範囲は変わらない | 理由を読んで直し、出し直す |
| 【個人開発領：保留】 | DM | 他の人のまだ確定していない範囲と重なっている | 何もしなくてよい。自動で審査し直される |
| 【個人開発領：却下】（重なった相手の承認が確定） | DM | 保留していた届出が、相手の確定で却下された | 範囲を変えて出し直す |
| 【個人開発領：Bot形式審査（仮承認）】 | 専用チャンネル | まとめて出された届出が条件を満たした（まだ確定していない） | DMの確認のボタンを押す |
| 【個人開発領：本人確認】（ボタン2つ） | DM | 誰かが自分の分をまとめて届け出た | 内容を確かめて、72時間以内にどちらかを押す。心当たりがなければ「取り下げる」 |
| 【個人開発領：本人確認（削除）】（ボタン2つ） | DM | 自分の個人開発領を削除するグループの届出が出た | よく確かめてから押す。押して成立すると元に戻せない。心当たりがなければ「取り下げる」を押して運営に相談 |
| 【個人開発領：Bot形式審査（却下）】（本人が取り下げ・期限切れ） | 専用チャンネル | まとめて出された届出が、本人の確認なしで終わった | 必要なら自分で出し直す |
| 【個人開発領：同時処理グループ却下】 | 専用チャンネル | グループの誰かの届出が成立せず、全体が却下された | 原因を直して、グループをやり直す |
| 【個人開発領：撤回】 | DM | 承認が運営者に撤回された | 理由を読み、運営の審査の結果を待つ |
| 「処理中にエラーが発生しました。運営に確認を依頼しました。」 | DM | 画像の処理がくり返し失敗した | 運営に対応の仕事が回っている。しばらく待ってから出し直す |

## 運営者の操作（承認の撤回）

ここからは運営者が行う操作です。参加者は実行できませんが、承認のあとに運営側で何が起きるかの説明として読めます。

ルールでは、届出が要件を満たすかを審査するのは運営です（旧ボーダー外の個人開発領に関するルール特例第4条第1項）。運営botの承認は機械的な条件の確認なので、運営者は承認のあとに届出を確かめ、必要なら撤回します。

1. 専用チャンネルの承認の投稿に付いている「撤回する（運営者）」ボタンを押します。承認から24時間以内だけ使えます。代表者による一括申請は、本人が確認して正式に承認された時点から24時間です。
2. 撤回の理由を入力して確定します。運営者1人で実行でき、ほかの運営者の同意は要りません。
3. 承認は効力を失います。届け出た人には、撤回した運営者の名前と理由がDMで届きます。
4. 運営投票（運営者どうしの秘密投票）で審査し直すための仕事が、運営に自動で回ります。運営投票の流れは[運営の承認](/docs/opsbot/modvote/)にあります。
{: .steps}

- 撤回は、実行した運営者の名前とともに運営botの記録に残ります。承認・却下・仮承認・グループの成立・不成立も記録されます。
- 代表者による一括申請やグループは、本人が確認しないと72時間で却下になります。イベントなどでまとめて届け出たときは、対象の人にDMの確認を促します。
- 画像の処理がくり返し失敗した届出は、運営専用のチャンネルに「【要対応】」の投稿が出て、優先度の高い仕事として運営に回ります。
- 参加者から「なぜ却下されたのか」と聞かれたときは、却下の投稿に書かれた条件の番号（①〜⑧）から、上の「却下されたとき」の表で原因を説明します。
